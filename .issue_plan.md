Implementation Plan — Enhance UI/UX (issue #17)

Goal
Improve clarity and feedback in the game's UI with minimal, safe changes that are fully client-side and covered by tests.

Small scoped checklist (implementation steps)
1. HUD polish
   - Add small SVG/emoji icons next to `spice`, `carried`, `bcount`, `ucount` in the HUD.
   - Tighten spacing and add aria-labels for accessibility.
2. Tooltip system (non-blocking)
   - Implement a lightweight tooltip element that follows the mouse when hovering units/buildings.
   - Tooltip shows: name, HP, carried/capacity for harvesters.
   - Keep logic isolated in `js/ui.js` and unit-tested.
3. Selection visuals
   - Improve selection stroke to a dashed ring and add multi-select support (shift+click) in `input.js`.
   - Add box-select (mousedown drag) for multiple units.
4. Keyboard shortcuts
   - Implement basic hotkeys in `input.js`: B (build barracks), T (train trooper), Space (center camera on base).
   - Document hotkeys in `README.md` under a new 'Shortcuts' section.
5. Colorblind mode toggle
   - Add a simple palette toggle in `css/style.css` and a small toggle in the HUD.
6. Tests
   - Add unit tests for selection logic and tooltip content in `tests/ui.test.js`.

Implementation notes and constraints
- Keep rendering code unchanged except small HUD and tooltip overlays.
- Avoid adding heavy assets; use simple vector drawings and CSS.
- Keep changes backwards-compatible and add tests for new logic.

Acceptance criteria (verifiable)
- HUD displays icons and aria-labels.
- Tooltip appears on hover with correct info.
- Selection visuals updated and multi-select works.
- Hotkeys function and README updated.
- Colorblind toggle visibly changes HUD colors.
- Tests added and all tests pass locally.
